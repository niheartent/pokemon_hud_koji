# 代码边界

## 数据与业务核心

当前固定原版位于 src/shared/upstream/pkm-hud.js，manifest.json 校验版本、提交和 SHA-256。两份历史原版 JSON 仅用于历史元信息和回归参考。

存取精灵、装备、MVU 持久化、资产保护、网络图源、形态解析与刷新调度由核心负责。美化层不绕过这些保护。

## 自有展示层

presentation.js 是由已接受的原版 v3.3.29 一次迁入的 111 个展示组件和根布局。此后由本仓库维护，不从远程核心重新提取。它涵盖训练家、队伍、附近、背包、盒子、战场、图鉴、详情、设置、DIY 表单与地图等模板。继承的函数名和 data-* 属性是接入现有业务交互的契约，不代表界面继续由上游生成。

presentation-boundary.js 在构建或检查更新时：

1. 验证启动作用域与 presentation-contract.json 的功能／数据接口。
2. 替换上游同名展示函数；如果上游删了模板，补入自有模板。
3. 排除原版 CSS 的初始化、追加和注入，提供独立样式安装。
4. 将核心 render 的根 HTML 挂载改接自有 kojiRootHTML。
5. 固定 TYPE_COLORS 和 NEARBY_TYPE_COLORS；属性语义仍来自业务数据。

它仅在合成时执行 AST 解析，不在逐帧渲染时解析源码。单个当前实例安装一个带 data-koji-owner 标识的主样式。

## 两套界面

黑白的 bw2-core-adapter.js 接入双屏挂载、缩放、页面生命周期与更新。它适配自有模板，不再寻找远程 CSS 初始化。bw2-native-base.css 的名称保留历史来源，文件已经是本仓库独立维护的固定基础；其余 bw2 CSS／JS 提供具体页面。

剑盾的 swsh-adapter.js 组合自有基础模板，使用有界缓存保留节点。swsh-foundation.css、swsh-hud.css 和 swsh-colors.css 分别负责固定基础、布局和明暗主题；核心调色设置不控制这些主题。

黑白独立版裁剪兼容包和更新器，自有模板及资源只保留需要的运行副本。

## 尚存的功能接入边界

上游是一个闭包式脚本，没有官方可导入 SDK。目前的功能契约仍位于同一源码作用域：组件调用图像／数据服务，业务处理器依赖约定的 data-* 属性与容器。核心 render／ensureHud 提供事件绑定、窗口和刷新生命周期；我们替换根模板，但保留这些功能处理。

因此当前解决的是远程模板与 CSS 的依赖，并非保证未来任意宿主 API／事件处理重写都能兼容。若要彻底独立到模块 SDK，需要另行拆分核心业务层及宿主桥，自己长期维护上游混合函数中的功能改动。不能靠删掉接口校验达到兼容。

## 更新与验证

koji-updater.js 同时检查核心和对应美化通道，校验版本、通道与 SHA-256，再合成，用户点击后安装。koji-bootstrap.js 比较核心和美化双版本，缓存按通道隔离。

完整业务回归检查存入／取出／装备、页面、配色、首次绘制、真实 IndexedDB 更新与刷新。style-isolation 测试额外删除原版全部自有组件对应函数及 CSS，验证两套界面实际样式一致，并打开详情与八个页面。测试运行于模拟酒馆，不写用户真实角色卡。
