# 剑盾主题管理

## 原因与结构修复

旧兼容器在 `var css=...` 后立即追加美化 CSS，但新版核心随后还有多次 `css+=...`，同优先级的原版规则会覆盖美化规则。附近卡片的白天选择器还用了 `:where()`，令根容器的优先级归零。结果是原版深色半透明背景、原版浅色文字与美化白底混用。

v1.4.8 起语法定位 `style.textContent=css`，禁用原版 CSS 初始化和追加，在此之前直接赋值剑盾自己的样式包。只加载本地受版本管理的 `swsh-foundation.css`、`swsh-hud.css`、`swsh-colors.css`。运行时不再加载新核心 CSS。保留原版业务函数；接口缺失或不唯一时拒绝更新合成。

## 配色原则

参考 [IBM Carbon 的分层与主题规则](https://www.carbondesignsystem.com/building-blocks/foundations/color/guidelines)：用颜色角色描述用途，背景、文字和边框成组切换。中性背景负责信息层次，红色负责剑盾视觉特征与选中状态，状态色用于战场增益、减益及规则。

参考 [W3C 正文对比度要求](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)：验证的普通正文及辅助文字至少达到 4.5:1。测试结果是选定信息内容的覆盖，不代表整个 HUD 已完成无障碍认证。

| 用途 | 白天 | 暗色 |
| --- | --- | --- |
| 卡片 | 白色 | 深蓝 |
| 标题与嵌套区域 | 灰蓝 | 深灰蓝 |
| 正文 | 深灰蓝 | 浅灰蓝 |
| 辅助文字 | 较浅的深灰蓝 | 较暗的浅灰蓝 |
| 强调色 | 深红 | 浅红 |
| 增益 | 深绿 | 亮绿 |
| 减益 | 深红 | 浅红 |

对应变量与组件颜色集中在 `src/swsh/swsh-colors.css`。已迁移的训练家与折叠栏目颜色从旧布局文件删除，附近卡片的旧白天色块也已删除，避免追加多套冲突的颜色规则。其余模块后续按功能迁移，不在此次重写业务代码。

字体栈使用 `--swsh-font-ui`；黑白使用自己的 `--bw2-font-ui`。主题配置保存在各自源码并嵌入各自美化包，不以原版配置缓存作为来源。暗色偏好仍使用剑盾专属 `pk_swsh_dark_theme`；黑白有自己的缩放和折叠设置，不读取剑盾主题偏好。

折叠栏目强调条使用独立的 `--swsh-fold-accent`：白天为深红，暗色为浅蓝。品牌色与栏目强调色分别管理，避免暗色栏目再次混入白天的红条。

附近属性顶边及稀有标识继续使用原版元数据，避免用一整块饱和色承载正文。背包、人际关系有独立边框、标题底色和强调边，避免与画布混成一块。战场正文、辅助文字、战术和状态采用各自角色。

## 主题偏好

`pk_swsh_dark_theme` 没有保存值时默认暗色。值为 `0` 时保持白天，值为 `1` 时保持暗色。升级不清空用户选择，也不新增网络请求或监听器。

设置仅提供此两种固定配色。主题色预设、选色器、深浅、文字颜色组在生成 DOM 时删除，原版无法再为它们绑定事件。新版核心的 `pkThemeApplyScheme` 由美化层停用，原版的 `--pk-*` 背景与强调角色映射到当前固定主题；以前保存的色相和深浅不再污染界面。设置页的标题、选项和辅助文字由同一颜色文件管理。

## 验证

`test_swsh_colors.cjs` 使用真实渲染器、隔离模拟酒馆和固定战场数据，测试内置核心与实际 v3.3.19、1000/360 像素视口、明暗两种主题，共 8 组。测试颜色覆盖训练家姓名与徽章文字、展开资料、背包标题、关系数值、附近名称数量、战场数值招式、战术和增减益。

默认暗色、设置保存白天后刷新仍为白天、无横向溢出、没有 MVU 写入和页面异常也在验证范围内。测试图片使用占位资源；像素精灵素材不影响此次颜色规则。报告与页面截图输出至忽略的 `HUD美化版-交付/` 目录。

`tests/style-isolation.cjs` 将真实 v3.3.19 的原版 CSS 改成荧光背景、荧光文字和不同字体，再分别合成黑白与剑盾。测试要求前后生成的实际样式文本完全相同，且浏览器中的字体、文字、背景和边框计算值一致。它不模拟任意上游 DOM 重构；这种变更仍需要渲染适配。
