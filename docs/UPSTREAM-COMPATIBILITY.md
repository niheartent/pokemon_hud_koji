# 弦九核心适配与后续检查

## 当前适配

两套正式导入包以及黑白独立版内置 v3.3.29。核心源码仅维护一份：`src/shared/upstream/pkm-hud.js`；`manifest.json` 固定上游 Git 提交、版本与 SHA-256。构建验证哈希，避免原版同版本号静默修改导致产物无法复现。旧 JSON 保留历史元信息与旧版回归参考，已不作为当前业务核心来源。

之前的失败来自对原版样式注入位置的依赖。剑盾 v1.6.0／黑白 v0.4.0 进一步取消了这一依赖：共享 `presentation-boundary.js` 在合成时排除原版 CSS 构建与注入，安装自有样式；`presentation.js` 提供 111 个固定组件函数及根布局。下载的新核心中的同名模板不会用于生成最终界面，缺失的模板由本地包补齐。

模板是从已接受的 v3.3.29 一次迁入并由本仓库维护的代码，不会随核心下载重新提取；剑盾装饰器现在只组合本地模板。`presentation-contract.json` 记录组件需要的 54 个服务函数、关键状态以及固定属性色表；缺失功能接口会拒绝合成。

核心的图源映射、Mega 形态候选、等级滑块调度和数据诊断保留。真实浏览器验证主页、详情及八个页面；额外模拟删除全部上游组件和 CSS，验证仍能启动、打开这些页面且实际样式完全一致。完整业务和配色回归另外运行。

## 如何检查下一版

1. `npm run build` 构建当前固定核心。
2. `npm run check:upstream` 获取上游当前文件对应提交，在内存中执行语法和接口合成检查。候选源码与报告仅写入忽略的 `artifacts/`。
3. PowerShell 设置 `$env:UPSTREAM_CANDIDATE='artifacts/upstream-candidate.js'` 后运行 `node tests/upstream-compatibility.cjs`，结束后 `Remove-Item Env:UPSTREAM_CANDIDATE`。在模拟宿主中执行候选，不操作真实聊天。
4. GitHub Actions 的 **Check latest Xianjiu core** 可手动运行同一检查，下载报告。它没有推送或发布权限。
5. 确认上游差异与浏览器检查后，更新共用快照及 manifest，增加美化版本，运行 `npm run build`、`npm test`、`npm run package`、`npm run verify`，再发布新标签。

## 可兼容与需要人工适配的边界

- 上游页面模板、样式颜色和原版 CSS 注入位置变化：不会进入我们的展示层；甚至可以没有原版模板和 CSS。
- 核心新增图源、形态映射、业务字段：保留业务；新增字段要由我们明确接入模板，不自动继承上游 HTML。
- 更新器检查和安装分离、版本与数据库身份、唯一注入点：明确校验，失败时不安装未知合成包。
- 关键功能函数改名、作用域搬迁、MVU 数据模型／宿主 API 改动、交互绑定改变：必须更新功能适配和运行测试，不能承诺自动兼容。
- 黑白双屏布局仍适配核心 render／openPage 的挂载与生命周期；剑盾同样使用核心交互绑定。这里仍是源码作用域中的函数契约，不是弦九官方提供的独立 SDK。
- 固定基础、布局和主题由本仓库维护。上游 CSS 不参与最终样式；原版调色缓存不参与剑盾主题。

## 发布原则

核心与 UI 版本分别管理；同一版本文件不覆盖。GitHub 检查成功只表明覆盖到的接口和模拟场景通过，不会自动发布。新增业务场景需加专门验证，不能用单纯语法通过代替运行验证。
